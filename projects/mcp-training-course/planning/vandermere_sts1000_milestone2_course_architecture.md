# Milestone 2 Course Architecture

# STS-1000 Sales Readiness: Stabilizing the Enterprise Workflow Stream

## 1. Purpose of This Document

This document defines the course architecture for the first version of the **STS-1000 Sales Readiness** training experience.

The course is designed as a short, engaging, intentionally over-serious sales enablement program for Vandermere Applied Dynamics' fictional flagship product, the **Synaptic Throughput Stabilizer STS-1000**.

The project should demonstrate:

- short-form HeyGen avatar-based instructional video
- Vimeo-hosted course video delivery
- static instructional and reference content
- searchable enterprise knowledge materials
- chatbot interaction grounded in video transcripts and static course resources
- a deliberately absurd but internally consistent fictional product world

The goal is not to create a long LMS-style certification program. The goal is to create a compact core training path embedded inside a much larger, mock-enterprise knowledge base.

The working model is:

> **A short required course inside an unnecessarily deep enterprise knowledge system.**

## 3. Course Description

**STS-1000 Sales Readiness** teaches Vandermere sales professionals how to understand, explain, position, and sell the **Synaptic Throughput Stabilizer STS-1000**, the world's first kinetic enterprise ballast for physicalized workflow architecture.

Learners will explore the STS-1000's core product story, primary machine anatomy, buyer pain points, use cases, objection-handling guidance, and enterprise deployment model. The course combines concise instructional videos with searchable reference materials, technical diagrams, sales guides, and internal field documentation.

By the end of the course, learners should be able to explain how the STS-1000 stabilizes procedural turbulence, cools overheated decision environments, regulates workflow pressure, and preserves enterprise velocity during periods of operational friction.

They should also know when to stop talking.

## 6. Course Design Principle

The course should preserve a clear boundary between the **required learning path** and the **expanded knowledge base**.

## Required Learning Path

This is the concise set of materials every learner must complete.

It should be limited to:

- 6 videos
- a few key terms per module
- a small number of knowledge checks
- one final readiness checkpoint

## Expanded Knowledge Base

This is the larger body of searchable support material.

It may include:

- deeper product descriptions
- subsystem reference pages
- diagrams
- glossary entries
- sales cards
- fake technical briefs
- deployment advisories
- field notices
- internal memos
- objection-handling sheets
- industry use case pages
- transcript pages

The knowledge base can be intentionally excessive. The required course should not be.

- completion certificate
- source citations in chatbot answers
- search result type filters
- static slides for each module
- downloadable one-page sales guides
- image gallery of the STS-1000 and HTA-700

## V1 Should Not Include Yet

- full LMS user management
- SCORM/xAPI
- complex authentication
- real learner analytics
- deep admin CMS features
- more than 7 required videos
- multiple product lines
- long-form technical manuals
- deeply defined power-substation lore
- a real-time transcript sync system unless easy to implement

## Operating Rule

If a detail is funny but not required for sales readiness, it belongs in the knowledge base, not in the required video path.

The HTA-700 is an external cryogenic cooling architecture installed outside the customer facility. One HTA-700 can support up to seven STS-1000 operating units. Larger campuses may deploy multiple HTA-700 units in serial cryogenic array, optionally paired with a Vandermere Grid Confidence Substation.

# 12. Search and Chatbot Content Strategy

## Purpose

The course should support a simulated enterprise search experience where learners can search across multiple source types:

- Vimeo videos
- video transcripts
- static documents
- glossary entries
- slides
- diagrams
- field notices
- internal memos
- quiz explanations

The chatbot should be able to answer questions using both video-based and static sources.

## Searchable Source Types

| Source Type      | Example                               |
| :--------------- | :------------------------------------ |
| Video            | Video 3: Anatomy of the Stabilizer    |
| Transcript       | Text transcript of the anatomy lesson |
| Static document  | Core Logic Reservoir Overview         |
| Glossary entry   | Workflow Cavitation                   |
| Slide            | HTA-700 capacity diagram              |
| Field notice     | Reservoir Levels Below 15%            |
| Sales card       | CFO Pitch                             |
| Quiz explanation | Why STS-1000 is not workflow software |

## Chatbot Should Be Able To Answer

- “What does the Core Logic Reservoir do?”
- “Which video explains the HTA-700?”
- “Give me the CFO version of the pitch.”
- “What is workflow cavitation?”
- “When should I avoid positioning this as software?”
- “Find content about quote-to-cash.”
- “What are the signs that a customer is too small?”
- “Show me sources related to thermal reasoning.”
- “What should I say if IT asks about ERP integration?”
- “Why should I not call the HTA-700 a tank?”

## Desired Chatbot Answer Pattern

A strong chatbot response should include:

1. direct answer
2. short explanation
3. source references
4. related resources
5. suggested follow-up question

Example:

> The Core Logic Reservoir stores and stabilizes the customer's institutional logic profile. In sales conversations, describe it as the STS-1000's stabilizing heart. It absorbs operational shockwaves when procedural turbulence rises. Related sources: Video 3 transcript, Core Logic Reservoir Overview, Field Notice 12-A.

## Grounding Rule

The chatbot should stay inside the fictional Vandermere world. It should not try to correct the premise by explaining that the product is scientifically impossible unless the user explicitly asks about the fiction or implementation.

# 15. Quiz and Certification Model

## V1 Recommendation

Keep assessment lightweight.

Use:

- one knowledge check per video
- a final 5-question readiness quiz
- no complicated scoring logic
- no formal pass/fail requirement unless useful for the demo

## Knowledge Check Style

Questions should reinforce the product world and sales positioning.

They should not be too hard. The point is to make the course feel real, not to create a difficult test.

## Final Quiz Categories

The final quiz should include one question from each area:

1. product definition
2. machine anatomy
3. customer pain
4. sales positioning
5. deployment or HTA-700

## Completion Language

Suggested completion message:

> You have completed STS-1000 Sales Readiness. You are now prepared to discuss procedural turbulence, decision-temperature normalization, and the responsible positioning of kinetic enterprise ballast infrastructure in customer-facing conversations.

Optional certificate title:

**Certified STS-1000 Sales Readiness Associate**
