# 01. Project Overview

## Project name

**Vandermere Applied Dynamics / Synaptic Throughput Stabilizer STS-1000 Sales Readiness**

## Project type

Fictional internal sales-enablement training prototype.

The project presents a fake enterprise hardware product, the **Synaptic Throughput Stabilizer STS-1000**, as if it were a real capital-infrastructure solution for enterprise workflow dysfunction. The content deliberately treats absurd pseudo-technical ideas with polished enterprise-training seriousness.

The intended tone is:

**85% serious enterprise training, 15% absurd technobabble.**

## Core concept

Vandermere Applied Dynamics is a fictional company that claims to have pioneered **Physicalized Workflow Architecture**. Unlike ordinary enterprise software, dashboards, workflow automation, or consulting, Vandermere claims to solve operational friction by installing physical machinery that stabilizes institutional workflow behavior.

The central belief:

> If business friction has measurable consequences, it must have physical properties.

The STS-1000 is the flagship machine. It is described as an enterprise-grade kinetic ballast that stabilizes workflow pressure, decision temperature, procedural turbulence, operational drift, and workflow cavitation.

Plain-language product explanation:

> The STS-1000 helps large organizations stop getting in their own way.

Vandermere-style product explanation:

> The STS-1000 anchors enterprise velocity inside a mechanically disciplined workflow field.

## Immediate product goal

The near-term goal is not a large academy or fully realized product universe. The v1 scope is a compact, polished learning experience:

- 5-7 short HeyGen avatar videos.
- Each video around 2-3 minutes, with no video longer than about 3 minutes.
- Static lesson pages with summaries, learning objectives, diagrams, resource cards, transcripts, knowledge checks, and related resources.
- Vimeo-hosted video playback.
- A learning environment built into the broader development project.
- A Vimeo-aware or course-aware chatbot/search experience that can answer questions from lesson transcripts and supporting resources.

## Broader development context

The STS-1000 course is part of a broader personal/prototype development environment that has used:

- Node.js / Express.
- EJS server-rendered pages.
- Vanilla JavaScript.
- SQLite.
- GitHub source control.
- VS Code and Codex-assisted development.
- PM2 for process management.
- Ubuntu server hosting.
- OpenLiteSpeed reverse proxy.
- Route53 DNS and Certbot HTTPS.
- Vimeo for hosting training videos and retrieving transcripts/caption data.

Those implementation details should be verified against the current repository before a contributor assumes exact paths or deployment commands.

## Project audience

The fictional audience inside the course is Vandermere sales professionals, sales engineers, customer-facing technical staff, or internal go-to-market teams learning how to explain and position the STS-1000.

The real audience for this handoff is a new contributor who needs to continue:

- course content writing,
- video production,
- image generation,
- lesson page implementation,
- transcript ingestion,
- search/chatbot integration,
- static resource creation,
- and general project cleanup.

## What not to do

A new contributor should not:

- make the product cartoonish, wacky, neon sci-fi, magical, or openly parody-labeled;
- turn the STS-1000 into an AI assistant, dashboard, SaaS tool, generic server rack, or HVAC replacement;
- add many unrelated machine components just because the universe is absurd;
- overload the short v1 videos with every invented term;
- rewrite current status as though planned modules are already complete;
- introduce more comedy than the current tone supports.

The project works because the fiction is delivered with controlled seriousness.
